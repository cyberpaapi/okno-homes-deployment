## Mobile full-preview correction

Fresh verification found an existing external-store hydration race made visible by the new theme. A trusted unsaved pearl update could arrive while a newly mounted mobile full-preview iframe was hydrating forest server HTML. The hooks read mutable preview maps outside React's snapshot, so a component could see draft values during its server-snapshot render. The shader and logo updated, while the main theme attribute retained forest; this left white headings over pearl. The same issue was reproduced independently in the browser and by a real server-render/hydrateRoot regression.

Preview values and collections now belong to the same immutable client snapshot as published content. Server hydration reads the empty server snapshot; then scalar, map and collection consumers receive the client draft consistently. Published refresh preserves the draft maps. Exact trusted-parent/origin checks and existing publication/storage/authentication semantics are unchanged. The original failing evidence remains under the external `preview-hydration/` and `independent/` folders, separate from the corrected candidate.
