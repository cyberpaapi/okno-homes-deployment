## Start here / Open and connect to the production admin

Production admin

1. Open https://okno-homes-deployment.vercel.app/admin. Bookmark this address; there is no public admin menu link.

2. Enter the owner-provided key in Admin token, then select Connect or press Enter.

3. Wait for Editor connected. If a storage or access error appears, stop and follow Troubleshooting.

4. Choose a page in the left navigation. Expand Home or Models for their nested editors.

What the fields mean: Admin token: the private action key, not website copy. Connect: loads the authenticated content snapshot.

Save: Connecting does not publish content.

Verify: Confirm the address ends in /admin and you are editing the intended page.

Note: Screenshots were captured from production on 16 October 2026 while signed out. Disabled controls illustrate their location, not a successful save. No key is included.


## Start here / Understand saved work before you publish

Every page / field and collection actions

1. Edit the correct field. The embedded preview may change immediately, before the change is saved.

2. Select Save draft next to each edited field. A list has its own Save [collection name] button.

3. Review every saved draft across the site. Publish is not restricted to the currently selected page.

4. Select Publish N drafts once and wait for Published revision [number]. Then verify the standalone public page.

What the fields mean: Unsaved edit: held only in the current tab. Saved draft: stored privately; visitors still see the prior publication. Published content: available to visitors.

Save: There is no general Save all button. N counts saved field/list entries, not pages or photographs.

Verify: Record the publication revision. Unsaved edits can remain in the preview even after other drafts were published.

Note: Coordinate with other editors. Publishing also releases their saved drafts if they are in the same content store.


## Start here / Preview privately, then check the real website

Page content / Draft site preview / Open page

1. Use Page content for the side-by-side editor and preview.

2. Select Draft site preview for a larger embedded view. It still includes unsaved and saved draft edits.

3. If the preview is slow, use Reload preview when offered. Avoid opening several media-heavy pages.

4. After publishing, use Open page. Make that standalone tab visible, allow a few seconds and refresh once if needed.

What the fields mean: Draft site preview: a private visual check. Open page: the published route, without the draft overlay.

Save: Changing view does not save or publish.

Verify: Check the affected text, media and links on the real page. Reconnect after preserving unsaved work if a persistence check is needed.

Note: A preview is not proof of successful storage, publication, enquiry delivery or device performance.


## Media basics / Replace an image without losing its description

Image field / collection photograph

1. Open the image field or list item you actually want to replace.

2. Use Drop a replacement here, or browse, Upload photograph or Replace image, according to that editor.

3. Wait for the uploaded file to appear. Review its framing; this editor does not provide a crop tool.

4. Update the related image description. Save both fields, or save the owning list, then review and publish.

What the fields mean: Supported images: JPEG, PNG, WebP, AVIF or GIF. Maximum file size: 100 MB. Image description: describe the subject and setting, not just the filename.

Save: Uploading alone is not Save draft. Credits and image descriptions are separate fields.

Verify: Check that the subject remains visible on phone and desktop. Keep existing media files until the maintainer confirms they are no longer referenced.

Note: Existing SVG/ICO asset paths do not mean the upload picker accepts new SVG/ICO files. Ask the maintainer to prepare those assets.


## Media basics / Replace a film and review its prepared result

Video field / rotation master / project film

1. Choose the matching video control and upload an MP4 or WebM file, up to 100 MB.

2. Keep one upload/preparation active at a time. Wait through the upload and preparation stages.

3. Inspect warnings, the prepared film and its poster. Use Cancel upload if necessary.

4. Save the relevant field or list. Publish only after the correct film, opening frame and ending have been reviewed.

What the fields mean: Prepared film: the playable/seekable delivery result. Poster: the still used before or instead of playback. Signature rotation master: can prepare rotation, Explore film and poster together.

Save: A cancelled or failed upload is not a successful save.

Verify: For scroll films, test forward motion, reversal and the final handoff on the standalone page.

Note: A film that plays normally may still be unsuitable for scroll seeking. Content replacement does not redesign scene timing or geometry.

## Projects / Check or correct pin coordinates

Projects > Globe pins > chosen pin

1. Open the pin and confirm the Place label.

4. Save Globe pins, publish and inspect its position and label on /projects.

What the fields mean: Latitude and Longitude are decimal degrees, not a street address. Move up/down changes list order; Remove pin changes the draft list.

## Recovery / Undo a field or collection mistake

Use original / Undo / Restore / corrected publication

1. For an unsaved error, re-enter the intended value. Reload only after preserving other wanted unsaved work.

2. Use original restores the built-in field default; save and publish it only if that is the desired result.

3. For a wrong saved draft or publication, re-enter the recorded previous value, save it and publish a reviewed correction batch.

4. For removed list records, use Undo/Restore where offered, review fields/order/dependencies, save the collection and publish.

What the fields mean: Disconnect clears tab access and unsaved state; it leaves saved drafts intact. The current UI has no universal Discard all drafts or whole-site revision rollback button.

Save: Ask the maintainer for whole-store recovery or removal of saved drafts without publication.

Verify: Verify the corrected public result and log the new publication revision. Never assume source default equals your last custom value.


## Troubleshooting / Resolve connection, storage and save errors

Connection notice / error message / preview recovery

1. Incorrect key / 401: check the owner-provided key and case, then reconnect. Do not publish until connection succeeds.

2. Storage unavailable / 503: stop writes and contact the maintainer. A rendered public page or preview does not establish working storage.

3. Reload before saving/publishing / 409: preserve unsaved work, coordinate with other editors, reload/reconnect and review newer content.

4. Validation / 422: correct the named field or relationship, save again and review the full saved draft batch before retrying Publish.

What the fields mean: For a slow preview, use Reload preview once and check the public page separately. For upload failure, finish/cancel the active task and check format/100 MB limit.

Save: Do not repeatedly click Publish or re-upload the same large file.

Verify: Record URL, page/section, action, non-sensitive error text, time and revision. Include a screenshot with the key hidden.

Note: This document does not certify current storage availability; no production content was changed for screenshot capture.


## Publication checklist / Finish, verify and hand over the change

Publish / Open page / Disconnect

1. Confirm every intended field/list was saved and all saved drafts are understood. Review copy, media, order and relationships.

2. Publish once; record the successful revision. Open the real public URLs and verify changed links and content.

3. Check one screen size at a time: phone, desktop and tablet when layout/wrapping is affected. Verify relevant model plans and old/new addresses.

4. After preserving intended work, reconnect/reload when persistence must be checked. Disconnect when finished and close extra media-heavy tabs.

What the fields mean: Log: editor/date, pages/sections, old/new values or media references, saved lists/fields, revision, URLs, widths and outstanding issues. Do not include keys or private media masters in the log.

Save: A content edit does not require starting a development server or running a build.

Verify: No unintended clipping, overlap, horizontal page scrolling, broken media or wrong destinations. Enquiry delivery needs its own check.
