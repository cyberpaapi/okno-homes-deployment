- Test public published values and private drafts separately. After a temporary publish, restore the original value and verify that restoration. Never call an admin UI action tested merely because the backing API or a component test passed.
- Keep incomplete new records savable as drafts. Publication must enforce the required fields. Press/news image, publication icon, date and credit are optional; article and project-note photographs are required.
- A zero/one/many collection test must inspect the actual public layout, not only schema validation. Process and Projects globe interactions are intentionally deferred by the approved plan.

API-authenticated checks can proceed locally, but browser-authenticated Save/Publish/Upload clicks remain unverified until the user connects the editor or a supported test harness can exercise that flow. ### Source-to-editor gaps found in this recheck

These are current implementation gaps, not failed runtime assertions. They take precedence over earlier checklist rows that said a page was “implemented.”

1. **P1 — Signature specification source mismatch.** The editor can publish display-only variant names, areas, spaces and prices in `ForzaExperience.tsx`, while the Configure route reads a separate catalogue. The same model can show different specifications on Explore and Configure. The approved plan calls for one canonical source.
2. **P1 — Journal featured selector absent.** `JournalHero.tsx` chooses the first press record. The explicit featured-record selector in the approved plan is not built.
3. **P1 — archived Project remains in an already-open detail page.** `useProjectContent.ts` falls back to its initial server prop when the published collection no longer contains the ID. A fresh request correctly returns 404, but the open tab violates the live-update expectation.
4. **P2 — unpublished multi-editor conflict.** Draft PATCH writes do not change the revision in `siteContentStore.ts`; stale-editor protection is only effective after a publish. The API returns 409 for all validation/storage failures, also obscuring the error category.
5. **P2 — exposed fields without a faithful consumer.** `home.variants.accessibleTitle` is not used by the V1/V2 hidden H1, and V1 `buttonLabel` has no corresponding button. A newly added Home variant has a dynamic route but no individual sidebar entry/preview. Signature's empty-gallery fallback uses the original poster rather than the published replacement.
6. **P2 — approved small-field gaps.** Project detail return/tab labels, Sustainability closing-photo credit, About assurance icon choices, Bespoke portal alt, and several approved CTA destinations remain hard-coded/unmapped. Hospitality links projects but lacks a chooser of an image from that project's gallery; it offers only inherited cover or path/upload override.
7. **Performance/operational limit — unproven at scale.** Video upload and derivative creation buffer files and run synchronously; there is no background job progress/cancel. Visible public tabs poll every 2.5 seconds and parse the local content history. The 100 MB validation and prior real 2.2 MB conversion test do not prove low latency for large films or many visitors. Durable shared CMS storage/auth is still an open deployment decision.
